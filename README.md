# תמלול פודקאסטים בעברית

אפליקציית ווב פרטית לנייד: מדביקים קישור לפרק בספוטיפיי ומקבלים תמלול בעברית, סיכום ונקודות עיקריות.

> **מצב נוכחי:** האפליקציה עדיין לא נפרסה ואין להריץ אותה בחשיפה ציבורית. ראו [מגבלות ידועות](#מגבלות-ידועות).

## איך משתמשים

1. נכנסים עם קוד הגישה של הבעלים.
2. מדביקים קישור לפרק, למשל <bdi>`https://open.spotify.com/episode/...`</bdi>.
3. האפליקציה מזהה את הפרק, מציגה ודאות זיהוי, ומתחילה לעבוד. אפשר לסגור את הדף ולחזור אליו.
4. בסיום מוצגים סיכום, נקודות עיקריות והתמלול המלא, עם כפתורי העתקה והורדה.

אם הזיהוי אינו ודאי, האפליקציה **עוצרת ומבקשת לבחור** בין הפרקים האפשריים במקום לנחש. זו החלטה מכוונת: תמלול של פרק שגוי גרוע מהודעת שגיאה.

הממשק בעברית, בפריסת <bdi>RTL</bdi> מלאה, ונבדק ברוחב <bdi>360px</bdi>.

## איך זה עובד

ספוטיפיי משמש **לזיהוי הפרק בלבד**. האודיו לעולם אינו מגיע מספוטיפיי אלא מקובץ ה־<bdi>enclosure</bdi> הציבורי של פיד ה־<bdi>RSS</bdi>.

```
קישור ספוטיפיי
  → אימות ונרמול הקישור
  → קריאת מטא־דאטה מדף ה־embed (שם התוכנית, שם הפרק, אורך, תאריך)
  → איתור הפיד הציבורי דרך ספריית iTunes
  → התאמת הפרק בפיד לפי כותרת, תוכנית, אורך ותאריך
  → תמלול שפורסם בפיד, ואם אין — הורדת האודיו ותמלול
  → סיכום ונקודות עיקריות בעברית
```

רכיבי הזיהוי וניתוח ה־<bdi>RSS</bdi> מבוססים על [steipete/summarize](https://github.com/steipete/summarize) (רישיון <bdi>MIT</bdi>), עם ייחוס מלא ב־<bdi>`src/vendor/summarize/NOTICE.md`</bdi>. ההתאמה עצמה נכתבה מחדש: הנרמול המקורי מוחק כל אות עברית, ולכן היה מחזיר את הפרק הראשון בפיד כאילו היה התאמה מדויקת.

## משתני סביבה

שמות בלבד. הערכים נקבעים בסביבת ההרצה ואינם נשמרים בקוד. ראו <bdi>`.env.example`</bdi>.

| משתנה | חובה | תפקיד |
|---|---|---|
| <bdi>`OWNER_ACCESS_TOKEN`</bdi> | כן | קוד הגישה של הבעלים. חייב להיות ארוך ואקראי; קודים קצרים או מוכרים נדחים בטעינה |
| <bdi>`SESSION_SECRET`</bdi> | לא | חתימת עוגיות הסשן. אם מוגדר, נבדק באותה חומרה כמו קוד הגישה, מפני שסוד חלש הופך את החתימה לניתנת לזיוף ועוקף את קוד הגישה. בהיעדרו משתמשים בקוד הגישה שכבר נבדק |
| <bdi>`TRANSCRIPTION_API_KEY`</bdi> | כן | מפתח לספק התמלול |
| <bdi>`TRANSCRIPTION_BASE_URL`</bdi> | לא | כתובת הספק. אפשר גם מודל מקומי בכתובת פרטית |
| <bdi>`TRANSCRIPTION_MODEL`</bdi> | לא | ברירת מחדל <bdi>`whisper-1`</bdi> |
| <bdi>`SUMMARY_API_KEY`</bdi> | כן | מפתח לספק הסיכום |
| <bdi>`SUMMARY_BASE_URL`</bdi> | לא | כתובת הספק |
| <bdi>`SUMMARY_MODEL`</bdi> | לא | ברירת מחדל <bdi>`gpt-4o-mini`</bdi> |
| <bdi>`PORT`</bdi> | לא | ברירת מחדל <bdi>`10000`</bdi> |
| <bdi>`TRUST_PROXY_TLS`</bdi> | לא | <bdi>`1`</bdi> כאשר <bdi>TLS</bdi> מסתיים בפרוקסי, כדי לסמן את העוגייה כ־<bdi>Secure</bdi> |

כל עוד חסר משתנה חובה, האפליקציה עולה אך **מסרבת לשרת** ומציגה מסך הגדרה עם שמות המשתנים בלבד.

## הרצה מקומית

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

הבדיקות אינן פונות לרשת ואינן דורשות מפתחות. הן דורשות <bdi>`ffmpeg`</bdi> ו־<bdi>Chromium</bdi>; בדיקות ה־<bdi>ffmpeg</bdi> מדלגות על עצמן אם הוא חסר, ולכן שווה לוודא שהוא מותקן.

```bash
sudo apt-get install -y ffmpeg
npx playwright install --with-deps chromium
```

## פריסה ל־Render

<bdi>`render.yaml`</bdi> מגדיר שירות <bdi>Docker</bdi> עם בדיקת בריאות ב־<bdi>`/healthz`</bdi>. הערכים הרגישים מוזנים בלוח הבקרה של <bdi>Render</bdi> ואינם נשמרים בקובץ. <bdi>`autoDeploy`</bdi> כבוי בכוונה: פריסה היא החלטה של הבעלים.

**האפליקציה טרם נפרסה ואין לחשוף אותה כרגע.** ראו מגבלות.

## פרטיות

- כאשר הפיד מפרסם תמלול, משתמשים בו ולא שולחים אודיו לאף גורם. זו הסיבה שהתמלול מהפיד מועדף.
- אחרת, **האודיו של הפרק נשלח לספק התמלול שהוגדר**, והתמלול נשלח לספק הסיכום. שני הספקים נקבעים על ידכם, וכל מה שנשלח כפוף למדיניות שלהם. אם זה אינו מקובל, אפשר להפנות את הכתובות למודל מקומי.
- קבצי אודיו והקטעים שנחתכו נמחקים בסיום, בהצלחה ובכישלון כאחד.
- תמלולים נשמרים בזיכרון התהליך בלבד ואינם נכתבים לדיסק. **הפעלה מחדש מוחקת אותם.**
- הודעות שגיאה של ספקים אינן מוצגות ואינן נרשמות: נשמרים רק קוד הסטטוס וקטגוריה, כדי שספק לא יוכל להחזיר מפתח או תמלול אל תוך הדף.
- כתובת האודיו וכתובת הפיד מוצגות תחת "פרטים טכניים" למשתמש המחובר בלבד.

## מה אמיתי ומה מדומה

**נבדק באמת:** אימות קישורים, ניתוח <bdi>embed</bdi> ו־<bdi>RSS</bdi>, מנוע ההתאמה והוודאות, שכבת הרשת כולל <bdi>redirects</bdi>, סיווג כתובות ונעילת כתובת מול שקע אמיתי, הורדה לדיסק עם מגבלות, חיתוך <bdi>ffmpeg</bdi> על אודיו אמיתי, ניקוי, תור, הזדהות, וממשק המשתמש בדפדפן אמיתי כולל העתקה והורדה. מתאמי הספקים נבדקים מול שרת <bdi>HTTP</bdi> מקומי.

**מדומה:** תשובות הרשת בבדיקות, והספקים עצמם. הנתונים של ספוטיפיי ו־<bdi>iTunes</bdi> נבנו לפי המבנה המתועד ולא הוקלטו משירות חי, מפני שאין גישת רשת בסביבת הפיתוח. **התנהגות אמיתית מול ספוטיפיי, iTunes או ספק בתשלום טרם הוכחה.**

## מגבלות ידועות

- לא נפרס, ואין לחשוף פומבית.
- לא בוצעה בדיקה מול פרק אמיתי בספוטיפיי או מול ספק בתשלום.
- הפעלה מחדש מוחקת עבודות ותמלולים. אין דיסק בתשלום ואין שמירה קבועה, בכוונה.
- אין ביטול של עבודה שרצה. עבודה תקועה מוגבלת בזמן על ידי פסקי זמן של הרשת ושל <bdi>ffmpeg</bdi>, אך לא ניתן לעצור אותה ידנית.
- עבודה אחת בכל רגע. זה מתאים למשתמש יחיד.
- שדה התיאור מוגדר כאות התאמה אך אינו מחושב עדיין.
